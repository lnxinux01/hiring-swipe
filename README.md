# 画像滑卡

**画像是手段，筛出最值得面试的简历是目的。**

面试官说不清「我要什么人」，但一眼能判断「这个不行」。
滑二十几张卡 → 反推出一个可解释的打分模型 → 直接拿去给真实简历排序。

## 跑起来

```
open index.html
```

零依赖、零构建、零后端。桌面和手机（touch 拖拽）都适配。

## 流程

1. **粘 JD**（没有也行）→ 自动预填硬性条件 + 指出「JD 没说的」
2. **粘候选人简历池**（或载入 80 份示例）→ JD 粗筛后，**滑的就是真人**；不足 8 份则退回合成对照卡
3. **滑卡** + 左上角管理硬性条件和「记住的偏好」（可逐条改文字 / 正负 / 指向维度 / 删除，按岗位给推荐种子）
4. **出画像** → 拿去给整池简历打分排序；偏好可存成「通用」（跨岗位自动带上）或「岗位专属」

## 视觉

Editorial Paper（借鉴 grain 的设计语言）× Interface Craft：纸白底、油墨字，
强调只用墨色的面积与实度；标题用 Fraunces 衬线；直线上的离散圆点做进度与分隔；
扇形牌堆 + 墨色细线纹理做 hero。深浅色都有。

## 为什么不是又一个简历匹配工具

领域里的标准做法是两段式：bi-encoder 召回 → cross-encoder / LLM 重排。
[ConFit v3](https://arxiv.org/abs/2605.09760)（Qwen3 + listwise RL）当前最强，能打过 GPT-5 和 Claude Opus 4.5。

但**这些工作都假设你已经有一份好 JD 和标注好的匹配对**。现实里 JD 是模糊的，没有标注 —— 这恰恰是 HR 消化不掉的那部分。

滑卡就是标注过程。24 次滑动产出的正是这些模型需要的东西：带标签的正负样本 + 一个权重向量，而且是**这一个面试官的**。

## 四步

1. **左上角设硬性条件** — 年龄 / 院校 / 语言 / 编程语言 / 实习时长 / 到岗天数。
   实时告诉你「100 个人里只剩几个」。牌堆会按条件重新生成（不是过滤），所以正交设计和统计有效性不受影响。
2. **滑卡** — 右滑可以聊 / 左滑不合适 / 上滑就要这种（权重 ×2）。
   点开简历可以对**具体某一段**打 ⊕⊖ 并写理由 —— 左右滑只有 1 bit，指着一段说「就是这个」信息量高 3 倍。
   随时能在输入框记一笔，系统会猜它在说哪个维度，立刻进模型。
3. **看它有没有在学会** — 每张卡模型先猜你怎么滑，再让你滑。
   命中率就是答案：一致的面试官 6 张时 4/6、18 张时 10/10。猜不准时它会说清为什么，并给一个能马上做的动作。
4. **拿去筛简历** — 粘真实简历，学到的权重直接打分排序，每个人标出加分/减分信号和被卡掉的原因。

## 它会顶你

- **学校是随机分配的对照变量**，本不该有规律。如果它跑出信号，说明你在无意识按学校筛人（置换检验 p 值为证）。
- **「单看有规律，控制其他维度后消失」**会被点名 —— 这是「凭感觉定标准、招来发现对不齐」最常见的来源。
- **硬性条件卡掉分数最高的人时会报警**，并让你回去松一条。

## 已知边界

- **滑够 24 张再看结论。** 10 张解锁，但 n<20 不可靠。
- **别全否。** 24 张里只剩 7 个正例，哪怕偏好完美可分也推不出来 —— 信息量真的不够。
- **简历抽取是规则匹配**，会看走眼。生产上换成 LLM 抽取即可，下游打分逻辑一个字不用改（它只吃维度向量）。
- **卡片是合成样本**，按维度构造，不是真人。
